# Консольная база данных primitive_db

## Установка и запуск

Для управления зависимостями, сборки и запуска проекта используется менеджер пакетов `uv`.

### Установка

Для установки зависимостей необходимо перейти в корневую директорию проекта и выполнить:

```bash
uv sync
```

### Запуск

Запуск приложения через `uv`:

```bash
uv run database
```

Также приложение можно собрать и установить как отдельную консольную программу:

```bash
uv build
uv tool install dist/*.whl
```

После установки приложение запускается командой:

```bash
database
```

Для переустановки приложения после внесения изменений:

```bash
uv build
uv tool install --reinstall dist/*.whl
```

## Управление таблицами

Консольная база данных, позволяющаю создавать, удалять и просматривать таблицы.

### Доступные команды

| Команда | Описание |
|---|---|
| `create_table <имя> <столбец:тип> ...` | Создать новую таблицу с указанными столбцами |
| `drop_table <имя>` | Удалить существующую таблицу |
| `list_tables` | Вывести список всех созданных таблиц |
| `help` | Показать справку по командам |
| `exit` | Завершить работу программы |

При создании таблицы поддерживаются типы данных `int`, `str` и `bool`.

### Пример использования

Запуск приложения:

```bash
uv run database
```

Если пакет установлен как консольная программа или активировано виртуальное окружение:

```bash
database
```

Создание таблицы пользователей:

```text
create_table users name:str age:int active:bool
```

Просмотр списка таблиц:

```text
list_tables
```

Удаление таблицы:

```text
drop_table users
```

Вывод всех команд:

```text
help
```

Завершение работы:

```text
exit
```

Все изменения таблиц сохраняются в JSON-файле.

## CRUD-операции

Консольная база данных позволяет добавлять, просматривать, обновлять и удалять записи в таблицах.

### Доступные команды

| Команда | Описание |
|---|---|
| `insert into <имя> values (<значения>)` | Добавить новую запись в таблицу |
| `select from <имя>` | Вывести все записи из таблицы |
| `select from <имя> where <столбец> = <значение>` | Вывести записи по указанному условию |
| `update <имя> set <столбец> = <значение> where <столбец> = <значение>` | Обновить записи по указанному условию |
| `delete from <имя> where <столбец> = <значение>` | Удалить записи по указанному условию |

### Пример использования

Создание таблицы пользователей:

```text
create_table users name:str age:int active:bool
```

Добавление записей:

```text
insert into users values ("Sergei", 28, true)
insert into users values ("Anna", 25, false)
insert into users values ("Ivan", 30, true)
```

Просмотр всех записей:

```text
select from users
```

Выборка записей по условию:

```text
select from users where age = 28
```

Обновление записи:

```text
update users set age = 29 where name = "Sergei"
```

Просмотр обновлённой записи:

```text
select from users where name = "Sergei"
```

Удаление записи:

```text
delete from users where ID = 2
```

Просмотр оставшихся записей:

```text
select from users
```

Все изменения записей сохраняются в JSON-файлах.

## Декораторы и обработка ошибок

Добавлены декораторы для обработки ошибок, подтверждения действий и измерения времени выполнения функций.

### Обработка ошибок

Декоратор `handle_db_errors` перехватывает исключения `KeyError`, `ValueError`, `TypeError` и `FileNotFoundError`, 
выводит сообщения об ошибках.

Например, при попытке повторного создания существующей таблицы:

```text
create_table users name:str age:int active:bool
```

Выводится сообщение:

```text
Ошибка: Имя таблицы users уже использовано
```

### Подтверждение действий

Декоратор `confirm_action` запрашивает подтверждение пользователя перед удалением таблицы.

Пример:

```text
drop_table users
```

Программа запрашивает подтверждение:

```text
Вы уверены, что хотите выполнить "удаление таблицы"? [y/n]:
Введите ответ:
```

При вводе `y` таблица удаляется, при вводе `n` операция отменяется.

### Измерение времени выполнения

Декоратор `log_time` измеряет время выполнения функций и выводит результат в консоль.

Пример сообщения:

```text
Функция create_table выполнилась за 0.000 секунд
```

### Кэширование запросов

Реализовано кэширование результатов запросов `select` с помощью замыкания `create_cacher`.

При повторном выполнении одинакового запроса результат берётся из кэша без повторного вызова функции `select`.

После изменения данных кэш сбрасывается.
